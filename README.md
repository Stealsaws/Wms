# WMS คลังสินค้ากลาง — คู่มือติดตั้ง

เว็บแอปสำหรับจัดการสต็อกสินค้าที่ใช้ร่วมกัน 3 ทีม (A / B / C) พร้อม Admin
ควบคุมส่วนกลาง ตัดสต็อกแบบ atomic (กันกดพร้อมกันสต็อกติดลบ) ใช้ Supabase
เป็นฐานข้อมูล และ deploy เป็นเว็บ static บน GitHub Pages

## โครงสร้างไฟล์

```
wms/
├── index.html          หน้า Login
├── team.html            หน้าสั่งซื้อของทีม (ตะกร้า + ยืนยันซื้อ)
├── admin.html            หน้าจัดการสินค้า + สถานะคำสั่งซื้อ (Admin)
├── dashboard.html        แดชบอร์ดสรุปยอดขาย/สต็อก
├── assets/
│   ├── config.js         ⚠️ ใส่ Supabase URL + anon key ตรงนี้
│   ├── app.js             ฟังก์ชันช่วยที่ใช้ร่วมกันทุกหน้า
│   └── style.css
└── supabase/
    ├── schema.sql          ตาราง + RLS + ฟังก์ชันทั้งหมด (รันครั้งแรก)
    └── seed_products.sql   ข้อมูลสินค้า 48 รายการจากไฟล์ที่ให้มา (รันหลัง schema.sql)
```

## ขั้นตอนที่ 1 — ตั้งค่า Supabase

1. เข้า [supabase.com](https://supabase.com) → สร้างโปรเจกต์ใหม่ (ฟรีก็พอ)
2. ไปที่เมนู **SQL Editor** → วางเนื้อหาไฟล์ `supabase/schema.sql` ทั้งหมด → กด **Run**
3. วางเนื้อหาไฟล์ `supabase/seed_products.sql` → กด **Run** อีกครั้ง (จะโหลดสินค้า 48 รายการเข้าไป)
4. ไปที่ **Project Settings → API** → คัดลอกค่า:
   - `Project URL`
   - `anon public` key

## ขั้นตอนที่ 2 — ใส่ค่าการเชื่อมต่อ

เปิดไฟล์ `assets/config.js` แล้วแก้เป็นค่าจริงของคุณ:

```js
window.WMS_CONFIG = {
  SUPABASE_URL: "https://xxxxxxxx.supabase.co",
  SUPABASE_ANON_KEY: "eyJhbGciOiJI...",
};
```

## ขั้นตอนที่ 3 — เปลี่ยนรหัสผ่านเริ่มต้น

รหัสผ่านตั้งต้น (ตั้งไว้ใน `schema.sql`) คือ:

| ทีม | รหัสผ่านเริ่มต้น |
|---|---|
| Admin | `admin1234` |
| ทีม A | `teama1234` |
| ทีม B | `teamb1234` |
| ทีม C | `teamc1234` |

**กรุณาเปลี่ยนทันทีหลังติดตั้ง** — เข้าสู่ระบบด้วย Admin แล้วไปที่หน้า
"จัดการสินค้า" ส่วน **เปลี่ยนรหัสผ่าน** ด้านล่างสุดของหน้า

## ขั้นตอนที่ 4 — Deploy ขึ้น GitHub Pages

1. สร้าง repository ใหม่บน GitHub (public หรือ private ก็ได้ ถ้า private ต้องมี GitHub Pro/Team ถึงจะเปิด Pages ได้)
2. อัปโหลดไฟล์ทั้งหมดในโฟลเดอร์ `wms/` (ยกเว้นโฟลเดอร์ `supabase/` ก็ได้ ไม่จำเป็นต้องอยู่บนเว็บ แต่ใส่ไว้ก็ไม่มีผลอะไร) ขึ้น repo
3. ไปที่ **Settings → Pages** → เลือก Source เป็น branch `main` โฟลเดอร์ `/root`
4. รอสักครู่ จะได้ลิงก์ `https://<username>.github.io/<repo>/`
5. ทดสอบเข้าเว็บ ลอง login แต่ละทีม

## หมายเหตุด้านความปลอดภัย (สำคัญ)

- ระบบนี้ออกแบบให้ **ง่ายและไม่ซับซ้อน** ตามที่ต้องการ — ใช้รหัสผ่านต่อทีม
  ไม่มีระบบสมัครสมาชิกเต็มรูปแบบ
- การเขียนข้อมูลทุกจุด (ตัดสต็อก, แก้ไขสินค้า, เปลี่ยนสถานะคำสั่งซื้อ) ทำผ่าน
  ฟังก์ชันในฐานข้อมูล (`purchase_cart`, `admin_*`) ที่ **ตรวจรหัสผ่านซ้ำทุกครั้ง**
  ไม่ได้เขียนตารางตรงๆ จาก browser — จึงยังปลอดภัยแม้ anon key จะถูกมองเห็นได้
  (เป็นเรื่องปกติของเว็บ static)
- อย่างไรก็ตาม รหัสผ่านทีมจะถูกส่งไปกับทุกคำขอซื้อ/แก้ไข (ผ่าน HTTPS ที่เข้ารหัสอยู่แล้ว)
  หากต้องการความปลอดภัยระดับสูงขึ้น (เช่น มีพนักงานจำนวนมาก ต้องการ login
  รายบุคคล) แนะนำให้อัปเกรดเป็น Supabase Auth ในอนาคต

## กันกดพร้อมกัน (Race Condition) ทำงานอย่างไร

ฟังก์ชัน `purchase_cart` ใน `schema.sql` ใช้คำสั่ง SQL แบบนี้สำหรับตัดสต็อกแต่ละชิ้น:

```sql
update products
  set stock_remaining = stock_remaining - qty
  where code = ? and stock_remaining >= qty
  returning stock_remaining;
```

คำสั่งนี้ตรวจ "มีพอไหม" และ "ตัดสต็อก" **ในคำสั่งเดียวกัน** ภายใต้ row-lock
ของ Postgres เอง ทำให้แม้ทีม A และทีม B กดซื้อสินค้าตัวเดียวกันพร้อมกันเป๊ะๆ
ฐานข้อมูลจะประมวลผลทีละคำสั่งเสมอ — ใครถึงก่อนได้ก่อน คนหลังจะได้รับข้อความ
แจ้งว่าสต็อกไม่พอทันที ไม่มีทางที่สต็อกจะติดลบ

## การปรับแต่งต่อยอด (ถ้าต้องการภายหลัง)

- เกณฑ์ "ใกล้หมด" ตอนนี้ตั้งไว้ที่ ≤3 ชิ้น หรือ ≤15% ของสต็อกตั้งต้น
  (แก้ไขได้ในฟังก์ชัน `stockStatus()` ของแต่ละหน้า)
- อยากเพิ่มทีม D/E ในอนาคต แก้ `check (team in ('A','B','C'))` ในตาราง
  `orders`/`team_credentials` และฟังก์ชัน `purchase_cart` ให้รวมทีมใหม่
